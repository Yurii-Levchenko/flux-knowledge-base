# Як вносити зміни

Коротко: **створи гілку → зміни файл → відкрий Pull Request → хтось із команди погоджує → злиття в `main`**.

Повна інструкція з картинками для Mac і Windows — за посиланням, яке Юрій надіслав у чат команди.

## Найпростіший спосіб: прямо на сайті GitHub (нічого не треба встановлювати)

1. Відкрий потрібний файл у репозиторії та натисни **✏️ (Edit this file)**.
2. Внеси зміни.
3. Натисни **Commit changes…** і напиши коротко, що змінив. Наприклад: «Додав ціни Ludex».
4. Обери **Create a new branch for this commit and start a pull request** → **Propose changes**.
5. На наступній сторінці натисни **Create pull request**.
6. Напиши в чат команди: «PR на перевірку» + посилання.

**Новий документ:** у потрібній папці натисни **Add file → Create new file**. Назва — латиницею, з `.md` в кінці (наприклад, `mvp_scope.md`). Почни з шаблону `templates/TEMPLATE.md`.

## Як перевіряти чужий Pull Request

1. Відкрий вкладку **Pull requests** → потрібний PR → вкладка **Files changed**.
2. Перевір:
   - чи є джерела;
   - чи позначені гіпотези;
   - чи немає секретів і сирих даних.
3. **Review changes**:
   - **Approve** — усе добре;
   - **Request changes** — треба доробити (напиши, що саме).
4. Після погодження автор натискає **Merge pull request**.

## Правила документів
- Формат — Markdown (`.md`).
- На початку документа: автор, дата, статус (чернетка / готово).
- Факти — з посиланням і датою. Цифри AppKittie підписуємо «оцінка AppKittie».
- Припущення позначаємо **[гіпотеза]**.
- Великі файли (PDF, картинки) — лише якщо дійсно потрібні, до 10 MB.
- Секрети, коди доступу, особисті дані — **ніколи**.

## Якщо щось пішло не так
Нічого не зламається: зміни в `main` потрапляють лише після погодження, а історія зберігає кожну версію файлу. Напиши в чат — розберемося.
